# IEEE Access Paper Folder

This folder contains a repository-driven writing framework for preparing an IEEE Access journal manuscript from the current project. It is intentionally limited to evidence found in the repository: Python source files, JSON problem instances, configuration files, Mermaid diagrams, experiment logs, result JSON files, and generated plots.

No existing implementation files were modified to create this folder.

## Repository Topic Captured

The repository implements a genetic-algorithm-based task scheduling framework for application DAGs mapped onto a processor/router platform model. The implemented workflow contains:

- an inner scheduler GA in `GAImplementation.py`
- a public/static benchmark runner in `SchedulerGa.py`
- an outer GA hyperparameter tuner in `OptimizerGa.py`
- a post-run comparison pipeline in `CompareGaRuns.py`
- JSON application/platform instances from 30 to 100 tasks
- logged static, nested, validation, and comparison results under `logs/`
- Mermaid workflow and architecture diagrams under `Charts/`

The repository evidence supports a paper centered on nested genetic optimization for stochastic task scheduling, where the inner GA searches task order, processor allocation, message priority, and message path choices, while the outer GA tunes scheduler hyperparameters using weighted makespan/runtime objectives.

## Files In This Folder

- `IEEE_Access_Paper_Template.tex`: Directly usable IEEE Access LaTeX manuscript skeleton with placeholders, equations, tables, figures, and algorithms.
- `paper_outline.md`: Detailed section-by-section writing plan with rationale, repository evidence, required author input, equations, figures, tables, and IEEE Access guidance.
- `section_checklist.md`: Completion checklist for converting the template into a finished manuscript.
- `repo_to_paper_mapping.md`: Evidence map from repository files to paper claims, including unsupported topics that must not be claimed.
- `README.md`: This guide.

## How Repository Content Maps To Paper Sections

- Introduction: use `README.md`, `Charts/*.mmd`, and the CLI workflows in `SchedulerGa.py` and `OptimizerGa.py`.
- System Model: use JSON instance structure in `example_*T.json`, platform graph loading in `GAImplementation.py`, and path construction logic in `load_problem`.
- Mathematical Model: use only implemented makespan, communication-delay augmentation, precedence reconstruction, GA genome segments, and weighted outer objective.
- Proposed Method: use `NEW_GA_V2` in `GAImplementation.py`, `outer_ga` in `OptimizerGa.py`, and static benchmark logic in `SchedulerGa.py`.
- Experimental Setup: use `ga_config*.json`, instance sizes, `logs/`, and plots/results generated by the scripts.
- Results: use existing JSON/PNG logs as candidate evidence, but verify final selected runs manually before publication.
- Related Work: position around GA-based task scheduling, DAG scheduling, multiprocessor scheduling with communication costs, and hyperparameter optimization for evolutionary algorithms.

## Where Authors Must Write Manually

The generated template deliberately does not invent final claims. Authors must provide:

- final paper title and author block
- final problem-domain motivation and use case
- literature citations and comparison papers
- final selection of experiment runs to report
- statistical interpretation of logged comparisons
- publication-quality figures exported from the repository plots
- explanation of why some JSON fields are present but not enforced by the current implementation
- any claims about real-world deployment, reliability, deadlines, processor eligibility, redundancy, or fault tolerance

Mark unresolved claims as `Author Input Required` until verified.

## Where Equations Should Be Added

Equations should be placed in the LaTeX sections for:

- application DAG definition
- platform graph definition
- processor assignment
- communication/path delay
- task start and finish time reconstruction
- precedence constraints
- makespan objective
- inner genome encoding
- outer hyperparameter vector
- normalized weighted outer objective
- summary statistics and Welch t-test, if reported

Do not add reliability, redundancy, deadline satisfaction, or processor-eligibility equations unless the implementation is extended or the authors explicitly frame those fields as future work.

## Where Figures Should Be Inserted

Recommended figure sources:

- `Charts/CodeArchitetcure.mmd`: code architecture diagram
- `Charts/flowchart TD.mmd`: end-to-end workflow
- `Charts/Expworkflow.mmd`: experiment workflow
- `logs/*/*.png`: convergence, repeat stability, runtime tradeoff, diversity, validation, and comparison plots

Before publication, regenerate or export diagrams in a consistent IEEE-ready style.

## Final Submission Checklist

- Confirm every technical claim maps to a source file, config file, result artifact, or figure.
- Replace all `Author Input Required` placeholders.
- Add complete IEEE references.
- Verify selected logged results are reproducible or explain the exact run folders used.
- Ensure the manuscript does not claim implemented deadline constraints, processor eligibility constraints, reliability, redundancy, fault handling, or graph partitioning unless new evidence is added.
- Check that all equations match the actual scheduler reconstruction and objective functions.
- Convert repository plots to publication-quality vector or high-resolution raster figures.
- Compile `IEEE_Access_Paper_Template.tex` with the official IEEE Access LaTeX class/package setup.
